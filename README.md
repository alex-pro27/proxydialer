# ProxyDialer

HTTP/SOCKS5-прокси, который перенаправляет трафик через удалённые `socks5` и `http` прокси. Поддерживает несколько независимых слушателей, гибкую фильтрацию доменов и IP-диапазонов, маршрутизацию с приоритетами и горячую перезагрузку конфигурации.

## Возможности

- **Несколько слушателей** — каждый с отдельным upstream-прокси и правилами фильтрации
- **Два протокола на одном порту** — слушатель `dialer` одновременно принимает и HTTP-, и SOCKS5-подключения (протокол определяется по первому байту)
- **Маршрутизация (routes)** — объединение нескольких прокси в один слушатель с приоритетами
- **Фильтрация доменов и IP** — правила `only` и `exclude` с поддержкой wildcard-паттернов (`*.example.com`), CIDR-диапазонов (`91.108.4.0/22`, `2001:67c:4e8::/48`) и готовых списков `geosite:name` / `geoip:name`
- **Горячая перезагрузка** — конфигурация перечитывается при изменении файла или сигнале `SIGHUP`, без перезапуска
- **Аутентификация** — авторизация для upstream `socks5/http` прокси, HTTP Basic-авторизация для слушателей маршрутов

## Установка

```bash
git clone https://github.com/alex-pro27/proxydialer.git
cd proxydialer
go build -o proxydialer main.go
```

## Запуск

```bash
./proxydialer
```

По умолчанию ищет `config.yaml` в текущей директории. Путь можно переопределить переменной окружения:

```bash
PROXY_DEALER_CONFIG_FILE=/etc/proxydialer/config.yaml ./proxydialer
```

## Конфигурация

Файл `config.yaml` состоит из трёх секций: `proxies`, `routes` и опциональной `geodata`.

### Секция `proxies` — standalone-прокси

Каждый `dialer`-слушатель работает одновременно как HTTP-прокси и как SOCKS5-прокси:
протокол входящего подключения определяется автоматически. HTTP-режим поддерживает
`CONNECT`-туннели и обычные HTTP-запросы; SOCKS5 — только `CONNECT` без аутентификации.

```yaml
proxies:
  # Прокси без фильтрации — весь трафик идёт через него
  - dialer: 127.0.0.1:7492       # локальный адрес слушателя (если не указан — прокси только для маршрутов)
    proxy: 192.168.50.51:1818    # адрес удалённого upstream-прокси
    protocol: socks5
    username: user               # опционально (плоский формат)
    password: pass               # опционально (плоский формат)
    use: true

  # Прокси с фильтрацией — только перечисленные домены идут через прокси
  - dialer: 127.0.0.1:7493
    proxy: 192.168.50.52:1818
    protocol: http
    use: true
    only:
      - '*.github.com'
      - '*.openai.com'

  # Прокси с исключениями — все домены кроме перечисленных
  - dialer: 127.0.0.1:7494
    proxy: 192.168.50.53:1818
    protocol: socks5
    use: true
    exclude:
      - 'localhost'
      - '*.internal.corp'

  # Routing-only прокси — без dialer, используется только в routes
  - name: SPB                    # имя для ссылок из routes
    proxy: 127.0.0.1:6969
    protocol: socks5
    use: true
    auth:                        # вложенный формат аутентификации
      username: "user"
      password: "pass"
    exclude:
      - '*.yandex.ru'
```

### Секция `routes` — маршрутизация с приоритетами

Как и standalone-прокси, слушатель маршрута работает одновременно как HTTP- и
SOCKS5-прокси (протокол определяется по первому байту). Если задан `auth`, он
применяется в обоих режимах: HTTP Basic для HTTP и username/password для SOCKS5.

```yaml
routes:
  - proxy: 127.0.0.1:58580      # адрес слушателя маршрута
    use: true
    exclude:                     # пре-фильтр: домены, исключённые из маршрутизации
      - "*.microsoft.com"
    only:                        # опционально: пропускать только перечисленные домены
      - "*.example.com"
    auth:                        # опционально: HTTP Basic-авторизация для слушателя
      username: "route_user"
      password: "route_pass"
    rules:                       # правила выбора upstream-прокси
      "SPB":                     # имя прокси из секции proxies
        priority: 1              # меньше число = выше приоритет
      "US":
        priority: 2
```

### Поля `proxies`

| Поле | Обязательное | Описание |
|------|:---:|---------|
| `dialer` | — | Локальный адрес `host:port`, на котором слушает HTTP-прокси. Если не указан, прокси доступен только через `routes` |
| `proxy` | ✓ | Адрес удалённого upstream-прокси `host:port` |
| `protocol` | ✓ | Протокол прокси: `socks5` или `http` |
| `username` | — | Логин для авторизации на upstream-прокси (плоский формат) |
| `password` | — | Пароль для авторизации на upstream-прокси (плоский формат) |
| `auth.username` | — | Логин для авторизации на upstream-прокси (вложенный формат) |
| `auth.password` | — | Пароль для авторизации на upstream-прокси (вложенный формат) |
| `use` | ✓ | `true` — активен, `false` — пропускается |
| `only` | — | Список доменов и IP-диапазонов, которые идут через прокси; остальное — напрямую |
| `exclude` | — | Список доменов и IP-диапазонов, которые идут напрямую; остальное — через прокси |
| `name` | — | Имя прокси для ссылок из секции `routes` |

### Поля `routes`

| Поле | Обязательное | Описание |
|------|:---:|---------|
| `proxy` | ✓ | Локальный адрес `host:port`, на котором слушает маршрут |
| `use` | ✓ | `true` — активен, `false` — пропускается |
| `only` | — | Пре-фильтр: только перечисленные домены и IP-диапазоны участвуют в маршрутизации |
| `exclude` | — | Пре-фильтр: перечисленные домены и IP-диапазоны идут напрямую |
| `auth.username` | — | Логин для HTTP Basic-авторизации на слушателе маршрута |
| `auth.password` | — | Пароль для HTTP Basic-авторизации на слушателе маршрута |
| `rules` | ✓ | Карта `имя_прокси` → `{priority: N}`. Меньше `N` = выше приоритет |

### Алгоритм маршрутизации

При запросе к слушателю маршрута домен проходит три стадии:

1. **Пре-фильтр маршрута** — проверяются собственные `only`/`exclude` маршрута. Если домен не проходит — соединение идёт напрямую (Direct).
2. **Поиск only-совпадений** — среди всех прокси из `rules` собираются те, у которых домен входит в список `only`. Only-совпадения приоритетнее default-совпадений. При конфликте нескольких only-совпадений побеждает прокси с наивысшим приоритетом (меньшее число).
3. **Fallback на default** — если only-совпадений нет, выбирается прокси с наивысшим приоритетом, который **не исключает** домен (т.е. домен не в `exclude`). Если все прокси исключают домен — Direct.

Пример: SPB (priority: 1, `exclude: [*.yandex.ru]`) и US (priority: 2, `only: [*.github.com]`):

| Домен | Результат | Причина |
|-------|-----------|---------|
| `github.com` | US | only-совпадение (приоритетнее default) |
| `example.com` | SPB | default-совпадение (не исключён SPB) |
| `yandex.ru` | Direct | SPB исключает, US не в only |
| `*.microsoft.com` | Direct | исключён пре-фильтром маршрута |

### Аутентификация

**Аутентификация upstream-прокси** поддерживается в двух форматах (на выбор):

```yaml
# Плоский формат (совместимость)
username: user
password: pass

# Вложенный формат (рекомендуется)
auth:
  username: user
  password: pass
```

Если заданы оба — приоритет у вложенного `auth.*`.

**Аутентификация для маршрутов** — если в `routes[].auth` заданы `username` и `password`, слушатель маршрута требует авторизацию в обоих режимах:
- HTTP — заголовок `Proxy-Authorization: Basic <base64>` (при ошибке — `407 Proxy Authentication Required`);
- SOCKS5 — метод username/password (RFC 1929) с теми же учётными данными.

Если `auth` не задан — слушатель маршрута доступен без авторизации (и по HTTP, и по SOCKS5).

### Wildcard-паттерны и IP-диапазоны

В `only` и `exclude` поддерживаются паттерны вида `*.example.com`:

| Паттерн | Совпадает с |
|---------|------------|
| `example.com` | `example.com`, `api.example.com`, `foo.bar.example.com` |
| `*.example.com` | `example.com`, `api.example.com`, `foo.bar.example.com` |

> `*.example.com` покрывает и сам apex-домен, и все поддомены.
> Паттерн без `*.` (например `example.com`) так же совпадает со всеми поддоменами.

Также поддерживается точное совпадение IP-адресов и CIDR-диапазоны (IPv4 и IPv6):

| Паттерн | Совпадает с |
|---------|------------|
| `10.248.1.79` | `10.248.1.79` |
| `91.108.4.0/22` | `91.108.4.0` … `91.108.7.255` |
| `2001:67c:4e8::/48` | IPv6-адреса в диапазоне `2001:67c:4e8::` … `2001:67c:4e8:ffff:ffff:ffff:ffff:ffff` |

```yaml
exclude:
  - '91.108.4.0/22'
  - '91.108.8.0/22'
  - '2001:67c:4e8::/48'
```

### Готовые списки `geosite` и `geoip`

Вместо ручного перечисления доменов и IP можно ссылаться на списки в формате `geosite:name` (домены) и `geoip:name` (IP-диапазоны):

```yaml
proxies:
  - name: telegram
    proxy: 127.0.0.1:6066
    protocol: socks5
    use: true
    only:
      - 'geosite:telegram'
      - 'geoip:telegram'
```

| Паттерн | Что покрывает |
|---------|--------------|
| `geosite:telegram` | все домены Telegram (t.me, telegram.org, …) |
| `geoip:telegram` | все IP-диапазоны Telegram (IPv4 и IPv6) |
| `geosite:google` / `geoip:cn` | любые списки из баз |

Базы скачиваются автоматически при первом старте и кешируются. Каталог и URL можно переопределить секцией `geodata`:

```yaml
geodata:
  dir: /tmp                # куда сохранять geoip.dat и dlc.dat (по умолчанию /tmp)
  geoip: "https://cdn.jsdelivr.net/gh/Loyalsoldier/geoip@release/geoip.dat"
  geosite: "https://github.com/v2fly/domain-list-community/releases/latest/download/dlc.dat"
```

| Поле | По умолчанию | Описание |
|------|:---:|---------|
| `dir` | `/tmp` | Каталог для хранения файлов `geoip.dat` и `dlc.dat` |
| `geoip` | URL geoip.dat | Переопределение адреса базы GeoIP |
| `geosite` | URL dlc.dat | Переопределение адреса базы GeoSite |

Источники по умолчанию:
- **geosite** — `dlc.dat` от v2fly (список доменов).
- **geoip** — `geoip.dat` от Loyalsoldier (коды стран + категории `telegram`, `google`, `netflix`, `facebook`, `cloudflare` и др.).

Файл считается актуальным, если рядом с ним лежит sidecar `<имя>.url` с тем же URL источника. Если URL в конфиге изменился (или sidecar отсутствует), файл перекачивается заново.

> Если указанного списка нет в базе, правило не совпадает, а в лог выводится предупреждение.

## Горячая перезагрузка

ProxyDialer отслеживает изменения файла конфигурации и автоматически перезапускает затронутые слушатели. Также можно принудительно перезагрузить конфигурацию сигналом:

```bash
kill -HUP <pid>
```
